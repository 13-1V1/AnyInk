Recovery: snapshots, Web Locks, restore

Loads ProjectEditor + History with a two-glyph project and src/anyink/recovery. Edits, undo and redo go through the real History, so markDirty(history) fires the real way. Snapshots land in the IndexedDB database anyink, store recovery, one record per live session under session:g2_RECOVERYPAGE:<session id>, holding the project, its assets and its undo queue. Restore swaps the project into this page's editor (no app navigation).

Checks (Chrome or Edge)

  1. Edit once: within 3 s writes goes to 1 (or click snapshot now).
  2. Hold Edit down with the keyboard (Enter auto-repeats): writes still climbs at least every 3 s (max-wait), and last write says maxWait.
  3. Undo: generation goes up and the next snapshot holds the undone width (show my record: A width and queue match the readout).
  4. Close this tab without mark clean, reopen it: both lists below offer "Recovery page". The reopened page also toasts (log line) that unsaved work from an earlier session exists.
  5. Discard in the banner list: the tab list empties by itself (and the reverse).
  6. Restore: toast line, the A width and the undo queue come back, the old key is gone after the first snapshot, the lock is held again.
  7. Two tabs on this page: edit in both, mark clean in one: the other tab's record is untouched. Close the other: it is offered here.
  8. Break storage, then edit: one toast "Crash recovery could not save a snapshot (...)" and last error filled in; more edits within a minute do not toast again. Fix storage, edit: writes resume.
  9. Break storage, edit, then Forget: toast "Could not forget the snapshots: ..." (no uncaught error in the console) and timer pending stays true. Fix storage: the pending snapshot lands.
  10. Edit, wait for a write, reload; repeat five times. Both lists show at most 3 rows for "Recovery page" (the newest three); the older snapshots are gone from the store.
